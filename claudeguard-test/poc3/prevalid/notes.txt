## P7. (关键新发现) 节点出口健康在本轮预验时已变坏
实测时间线 (同一台 VPS 154.53.75.226, anytls:8450):
  - TCP {0x8450 可连通 (nc ok)
  - 引擎内 anytls 会话建立 "Update padding succeed" (debug 可见)
  - 但经隧道到任何 HTTPS 目标在 TLS 握手被 RST: example.com / example.org / claude.ai / discord.com 全 000
  - REST delay 测试 (GET /proxies/anytls-node/delay 各 URL) 全部失败
  - 对照: 直接 (root 侧) https example.org 200, 引擎 DIRECT 云路径 200 —— 出口隧道层坏
  - 且 PoC-2 当时 example.com 经隧道 = 200; 现在该域名经隧道也 000 (与 claude/discord 同病征)
推断: 节点池当日已病 (不排除 server 侧或该 VPS IP 被更宽的场景拉黑)。
处置 (已写进 run-e2e.sh): 加 "节点健康门" —— PHASE-A 先等探针 200 (最多 ~35s),
拿不到 200 直接中止并回滚, 让所有者换健康节点后重跑, 避免带病实验得出假 FAIL。
