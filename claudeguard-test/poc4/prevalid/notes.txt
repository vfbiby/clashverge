## P8. （新坑坐实）/$() 子壳变量不跨调用
iprobe 的 mock 计数器写在函数里经 $(iprobe) 调用 → 每次调用是新子壳, 计数器永远从
fork 刻的快照起步, 序列"冻住"（第一轮 bug: 全 000 / 全 200 二值假象）。**真实看门代码
无此形态**（WFAIL/WOK 计数器在 watch_loop 子壳体内自持, 不隔 $()）, 但任何"计数型
mock 探针"必须落盘（文件）跨子壳。已入 harness 注释, 供后续实验借用。

## P9. （关键发现, 直接改了包的设计）两个 BSD 端口语义坑
1. **127.0.0.2 非 root 不可 bind**: `bind udp 127.0.0.2:1053: can't assign requested address`
   （对照: 127.0.0.1 正常）—— macOS/BSD 只有已分配地址可 bind, Linux 式 127/8 全段可绑
   在 macOS 不成立; 需 `ifconfig lo0 alias 127.0.0.2`（root）才可。
2. **用户引擎持 [::]:53 通配 → 我们绑任何特定地址的 :53 UDP 一律 EADDRINUSE**:
   影子实验（prevalid/port53-sim-wild.yaml + port53-sim-specific.yaml, 全 1053 端口等比复刻）:
   引擎A写 listen 0.0.0.0:1053 → 实际 lsof 见 **IPv6 [::]:1053 通配**（mihomo 把 0.0.0.0
   归一成 v6 双栈）; 引擎B再试图 bind 127.0.0.1:1053 →
   UDP: `bind: address already in use`（被通配吃掉）; TCP: 正常 LISTEN。
   => 任务书"改绑 127.0.0.2:53 避让"的设想**两条腿都被实测否决**（①别名缺失 ②UDP通配墙）。
   => **设计变更（已回写 config-tun.yaml）**: 放弃 :53 插座, 系统 DNS 直接指向
   **198.18.0.53**（fake-ip 段内专用指针地址）→ 该查询走 198.18.0.0/16 窄路由进 utun →
   `dns-hijack: ['198.18.0.53:53']` 在 gvisor 栈内应答。全程**不占任何 :53 socket**,
   与用户引擎零冲突; DNS 接管本身也行进在实验边界（TUN）内。
   系统解析器确实只会查询 :53 端口, 198.18.0.53:53 恰好就是"端口53 的合法 setter 地址"。
