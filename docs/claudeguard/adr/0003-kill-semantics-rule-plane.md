# 「断」的语义定义在 TCP/规则面（REJECT 注入），不定义在 DNS 面

**Status**: accepted · 2026-10-20

通路不健康时的"断"由看门进程把专属出口策略组切换为 REJECT（本地 RST，实测 0.01s 生效，PoC-2 T6）；DNS 面继续正常应答，不追求"停发 fake-ip"。

**为什么**：实测证明 fake-ip 不感知出口健康——节点全死后 `dig claude.ai` 照常返回 fake-ip，连全新子域都照常新签发（PoC-2 T5）；mihomo 原生不存在"出口死了 DNS 停指路"的语义，硬做 DNS 面断要么改引擎要么在上层反复注入。而 REJECT 在规则面是原生动作、秒级生效、失败形态最干净（无悬挂连接）。体验梯度实测支撑分层：REJECT 0.01s < 本地死节点 ~2s < 真黑洞 5s。

**代价**（接受，须向用户解释）：DNS 应答与 TCP 断并存，会出现"域名能解析但连不上"的正常现象——产品日志与文案必须把这一点说清，否则会被当成本产品故障；同时看门进程必须常驻维持状态机，看门死则退化为 pf+hosts 兜底断。
